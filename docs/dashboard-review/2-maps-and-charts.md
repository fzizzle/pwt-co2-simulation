### Camera, aspect and controls

The map gets `0.76 × (1 − 0.05) = 0.722` of the paper height. Before any automatic margin growth it gets `0.722 × (560 − 38 − 64) ≈ 331 px`. At zoom 13.2 the plotted lap needs about 389 px north to south. The mean point of the placed samples gives about 224 px of track to the north and 166 px to the south. The camera has about 165 px in each direction. Widening the same map leaves this vertical limit in place. A phone can also run out of horizontal space. `dashboard/track_charts.py:75–84,150–153`

Fit the full circuit from `outline()`. Its geographic bounds are about 5.95960–5.97756° E and 50.42768–50.44622° N. With latitude `φ₀` at the centre, local width is `R Δλ cos φ₀` and height is `R Δφ`, with angles in radians. Spa is about 1.27 km east to west and 2.06 km north to south. The bare track has a width-to-height ratio of about 0.62. Keep north up and size the map around that tall shape. At wide widths, the run choices and lap readout can sit beside it. At narrow widths stack them above it. A rotated, equal-scale schematic could work for a short panel if it has a north arrow. Rotation adds little to the first fix. `pwt/trackmap.py:18–24,34–48` · `pwt/deck/track.py:27–55`

Use normalised Web Mercator for the actual camera. At bearing and pitch zero its coordinate span at zoom `z` occupies `512 × 2**z` pixels per world unit. Compute the midpoint in projected coordinates. For a map domain `W × H` and inside padding `px, py`, fit both dimensions. Use the **map domain** dimensions after subtracting margins and reserving control space.

```python
track = outline()
x = (track.lon.to_numpy() + 180) / 360
lat = np.deg2rad(track.lat.to_numpy())
y = (1 - np.arcsinh(np.tan(lat)) / np.pi) / 2

dx, dy = np.ptp(x), np.ptp(y)
cx = (x.min() + x.max()) / 2
cy = (y.min() + y.max()) / 2

aspect = dx / dy
W = min(available_map_width_px, 540)
H = round(np.clip((W - 2 * px) / aspect + 2 * py, 280, 500))
# Choose smaller label padding or fewer visible labels if the domain is too narrow.
scale = min((W - 2 * px) / dx, (H - 2 * py) / dy)
camera = dict(
    center=dict(
        lon=360 * cx - 180,
        lat=np.rad2deg(np.arctan(np.sinh(np.pi * (1 - 2 * cy)))),
    ),
    zoom=np.log2(scale / 512),
    bearing=0,
    pitch=0,
)
```

The explicit fit assumes the available width is measured. A server-side width guess with `width="stretch"` would bring clipping back as the sidebar or viewport changes. The installed Plotly 7.1 supports `map.fitbounds="locations"` when centre and zoom are unset. That path fits the real Plotly domain with a built-in 20 px inset. Start there if the deployed version supports it and the resize and animation checks pass. Use inward-facing names, a short landmark list on cramped maps and hover for every landmark. The requirements currently allow Plotly 5.24, so check the supported version range before relying on native fitting. If more edge clearance is needed, use the explicit camera with a measured client-side width, or compute a conservative camera from the narrowest supported plot width.
