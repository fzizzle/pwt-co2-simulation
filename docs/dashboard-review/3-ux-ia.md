# Dashboard UX and information architecture

I walked all ten sidebar destinations on the running local app at 1280 × 800 px and 390 × 844 px. I followed the menu in order and returned to Overview after changing its measure. All ten default views rendered without a Streamlit exception. The main content stayed within the phone viewport on each page. The phone test used a resized browser. It did not exercise a physical touchscreen or screen reader. Source references are relative to the repository root.

## Findings by impact

1. **High — workbook maps present calculated numbers as reported data.** Open Trace explorer on its default lap. “Paint the track with” offers “CO₂ emitted here”. Its g/km value is calculated from the reported grams and step distance. Power gets converted from W to kW and battery charge from fraction to percent. Hover also presents interpolated values between workbook segments. The interpolation note appears below the map. This conflicts with Overview's promise and makes a number copied from a tooltip hard to defend against the source sheet. Give workbook maps a source-specific set of measures, labels and hover values. Show original values and units at reported steps. Interpolation can draw the outline without creating extra numeric observations. Keep derived measures on model maps. See dashboard/views/1_Overview.py:45, dashboard/labels.py:37, dashboard/track_charts.py:50, dashboard/track_charts.py:103 and dashboard/track_charts.py:218.

2. **High — Data attaches a warning to the wrong workbook.** Open Data, leave the default filters and select Workbook cells. The plug-in hybrid NEDC electricity warning appears immediately above the source for the petrol Francorchamps eco workbook. The workbook picker always contains the whole catalog, irrespective of the visible filters. A visitor can also exclude the hybrid with the filters and then select its workbook without seeing the warning. In this dataset mode, use the selected workbook for the notice and omit the independent filters. Restrict the introduction to workbook datasets. It currently claims coverage of every other page. See dashboard/views/5_Data.py:42, dashboard/views/5_Data.py:62 and dashboard/views/5_Data.py:110.

3. **High — Compare can draw two different runs with identical encoding.** Choose the same powertrain on two cycles. Both traces get the same colour, solid line and marker. The legend names both, but the reader cannot reliably follow a line from its legend entry. Give left and right distinct dash patterns for every comparison. In Category view, the existing dash pattern helps within one powertrain, but a comparison across powertrains still relies on colour alone. Study B already uses hatching and hollow markers for provisional status. Preserve that convention. See dashboard/views/4_Compare.py:48, dashboard/charts.py:259, dashboard/charts.py:287, dashboard/views/2_Category_View.py:177 and dashboard/views/9_CO2_Sensitivity.py:140.

4. **High on phones — playback and scrub controls overlap.** On the Trace explorer map at 390 px, Play/Pause occupied x = 64–205 px and the slider occupied x = 121–340 px at intersecting heights. This creates about 84 px of shared control area. The plot gives them the same vertical anchor. Put them on separate rows at narrow widths. Fit the initial map to the circuit bounds at each width and check the corner labels at both widths. Current zoom is fixed, and corner text is 10 px. The “Battery charge” paint option can remain visibly selected on a petrol run while the map silently changes its underlying metric to speed apart from a caption. Offer only the available measures and show the active quantity beside its unit. See dashboard/track_charts.py:152, dashboard/track_charts.py:158, dashboard/track_charts.py:169, dashboard/track_charts.py:179 and dashboard/track_charts.py:220.

5. **Medium — the landing page sends readers to the wrong group and delays its main table.** The menu's order makes sense: reported data, model exploration, then reports. Overview says that Sizing and Study B are under “The model”; both are under “The reports”, and the list omits Cornering speed. At phone width the first comparison table started at y = 1083 px. The introductory elevation strip represents one fixed lap even when the user selects NEDC alone. Put the selected measure and matrix first, with its electricity caveat adjacent. Move the illustration into the circuit explanation. For backlog item 3, offer task links such as “Inspect one workbook trace” and “Compare model scenarios”. Findings belong on their respective study pages. Use “Model output” on direct entry to each model/report page. The Model page already explains why its CO₂ can differ from Overview. Preserve the owner-review and provisional labels on both saved studies. See dashboard/Overview.py:23, dashboard/views/1_Overview.py:50, dashboard/views/1_Overview.py:61, dashboard/views/1_Overview.py:97, dashboard/views/6_Model.py:87 and docs/superpowers/plans/2026-11-04-ui-clarity-backlog.md:23.

6. **Medium — related pages lose the reader's selection.** I selected Fuel consumption on Overview, visited Data, then returned. The measure reset to CO₂ per km. The identical-looking Powertrains and Cycles filters are created inside individual pages. Trace, Compare and Model also use separate run keys. Keep compatible workbook selections during a visit and offer a reset. Carry a specific run into Trace explorer when the user follows a link from a comparison. Keep workbook and generated cycles distinct. On phones the sidebar hides Overview's measure and Trace's axis, while Compare's Left/Right pickers are in the main body. Put primary controls next to what they change. See dashboard/layout.py:243, dashboard/layout.py:261, dashboard/views/1_Overview.py:74, dashboard/views/3_Trace_Explorer.py:47 and dashboard/views/4_Compare.py:44.

7. **Medium — repeated circuit sections bury the differences between tasks.** Category is good for all cars on one cycle or all cycles for one car. Compare is good for an arbitrary pair and its differing inputs. Trace is good for one run's signals. Category offers a quantity, overlay membership, column, axis and another run picker for the map. Its differing inputs come after the map. Compare promises differing inputs first but actually leads with reported totals. Put the comparison evidence together and link to a selected lap in Trace. For backlog item 4, trial category presets within Compare before retiring the separate page. Keep the generated-lap map easy to reach: Model's map currently sits below the full scenario matrix. See dashboard/views/2_Category_View.py:136, dashboard/views/2_Category_View.py:217, dashboard/views/3_Trace_Explorer.py:85, dashboard/views/4_Compare.py:36, dashboard/views/4_Compare.py:62, dashboard/views/4_Compare.py:98, dashboard/views/4_Compare.py:174 and dashboard/views/6_Model.py:130.

**Loading.** On the running local instance I could read each destination's heading within about 0.6 s of navigation. That measures warm navigation, not complete chart rendering or Cloud wake-up. Workbook and model loaders name the work in progress. Hybrid sizing calls its cached 616-size sweep and storage cases before rendering its title. Move its introduction above those calls so a cold visitor knows what is loading. Study B also prepares hidden report content and reads a download on an Explore rerun. Defer those operations until the report is requested. See dashboard/loaders.py:35, dashboard/views/6_Model.py:59, dashboard/views/7_Sizing.py:35 and dashboard/views/9_CO2_Sensitivity.py:192.

**Empty and error states.** Overview explains how to restore an empty filter. Category prompts for a run when its overlay is empty. Study B explains why a comparison can fail its engine check. Both saved studies stop on a missing primary results file with a repair message. A partially populated Study B file can still reach an unchecked baseline lookup; give the visitor the affected car and cycle if that row is missing. Error paths were inspected in source. I did not remove files from the shared checkout. See dashboard/views/1_Overview.py:86, dashboard/views/2_Category_View.py:155, dashboard/views/9_CO2_Sensitivity.py:65, dashboard/views/9_CO2_Sensitivity.py:86, dashboard/views/9_CO2_Sensitivity.py:108 and dashboard/views/10_Cornering_Speed.py:56.

**Contrast.** Default white text on the dark surface is legible. Muted chart text uses the same grey on both palettes, and small light-theme labels in that grey have only about 3.4:1 contrast against the defined light surface. Check the viewer-selected light theme too: the fallback can return the configured dark palette even after the live theme reports light. Preserve accessible numeric alternatives such as Track map's table. See .streamlit/config.toml:4, dashboard/theme.py:54, dashboard/theme.py:75 and dashboard/views/8_Track_Map.py:61.

## Recommendation

1. **Correct what a visitor can attribute to a workbook.** Restrict workbook map values and hover units, bind the Data warning to the selected file, and correct the navigation and source copy. Verify against a petrol lap and the plug-in hybrid NEDC workbook. Rough effort **1–2 days**.
2. **Make comparisons and phone maps readable.** Add independent line patterns, separate playback controls, fit the full circuit, and put the Overview matrix before the elevation illustration. Recheck at both widths with identical-powertrain runs. Rough effort **1–2 days**.
3. **Preserve context across tasks.** Carry compatible selections, link a comparison to its trace, and trial category presets in Compare. Keep direct access to the generated-lap map and saved studies. Test a classmate finding a differing input and returning to the same run before deciding whether to remove a destination. Rough effort **2–3 days**, including the walkthrough.
